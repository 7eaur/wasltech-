## أسباب بنيوية تأكدت من مراجعة المصدر
- `scripts/build.mjs` يبني CSS عامًّا ثم حزماً منفصلة للعائلات. لذلك حلول override في آخر ملف دون فهم ترتيب التحميل ليست مقبولة.
- `src/pages/project-detail.js` يفصل story وscope وservices في أقسام متتابعة؛ يجب تعديل المكونات/التخطيط الأصلي عند تصحيح الكثافة.
- `src/pages/process.js` يخرج أربع `process-phase` داخل `process-phases__list`؛ اتصالها البصري يقع في CSS الأساسي `src/styles/about-process.css`.
- `scripts/check-project-details.mjs` يشترط ثلاثة أقسام story ومحتوى scope؛ لا تُحذف لحل طول الصفحة.
- `scripts/check-quality.mjs` يفرض سقف CSS gzip قدره 16 KiB للصفحة؛ الحل الصحيح تحسين CSS وإزالة الزائد وليس تعطيل الفحص.
- README يقول إن main مصدر النشر، لذا هذا العمل معزول في فرع مستقل إلى اجتياز الفحص.

## استراتيجية إصلاح جذري
1. تحليل source of truth للتصميم: tokens/layout/typography والـ responsive breakpoints، واكتشاف التعارض والتكرار والقواعد غير المستعملة قبل أي تعديل شامل.
2. إصلاح الأنماط على مستوى المكونات المشتركة أو ملفات صفحات المصدر، لا استخدام `!important` أو تثبيت ارتفاعات تعطل RTL.
3. المحافظة على الهوية ومحتوى AR/EN، مع اختلاف مقصود بين Timeline / cards / editorial / image galleries.
4. حل 404 والصور بعد إعادة إنتاج الخطأ على نطاق منشور، لا الاكتفاء بتغيير CSS.
5. تشغيل `npm run vnext:verify` ثم `npm run vnext:verify:release` و`node scripts/check-final-media.mjs`؛ ثم مقارنة صور وقياس LCP/CLS/overflow والتنقل بالكيبورد.
6. إغلاق كل ID فقط بدليل: Commit + لقطة قبل/بعد + فحص ناجح. من دون ذلك يبقى **Open**.

## مراحل العمل
- **A** تأسيس سجل الفجوات + تدقيق ملفات وأنماط CSS + تحسين تسلسل صفحة «كيف نعمل».
- **B** الصفحة الرئيسية: لماذا وصل، الخدمات، الأعمال، فراغات الأقسام.
- **C** قوالب تفاصيل الخدمات والمشاريع والوسائط.
- **D** من نحن، التواصل، ابدأ مشروعك، الأسئلة، المقالات، الوظائف، القانونية.
- **E** إعادة إنتاج 404، فحص تحميل الصور، اختبارات متصفحات، أداء، توثيق وإغلاق.
