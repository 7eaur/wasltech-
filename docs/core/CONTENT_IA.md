# Wasl Tech VNext — Content, Information Architecture & Writing System

Status: CANONICAL CONTENT/IA AUTHORITY

## 1. Content principle

Every page has a job. Copy exists to help the visitor understand, decide, trust, or act.

Do not write pages merely to make them longer.

Writing style:
- clear;
- concise;
- confident without exaggeration;
- technical only when useful;
- human;
- business-aware;
- evidence-safe.

## 2. Primary information architecture

Primary navigation:
- الرئيسية
- الخدمات
- الأعمال
- كيف نعمل
- من نحن
- ابدأ مشروعك / تواصل

Supporting:
- FAQ
- 404
- privacy/terms only when real policy is approved
- knowledge/blog only when maintained

## 3. Homepage narrative

Recommended sequence:

1. Brand Hero — what Wasl Tech builds and why it matters.
2. Compact positioning/proof strip.
3. Service families — help visitor self-identify.
4. Selected work / proof.
5. Why Wasl / operating principles.
6. How we work.
7. Relevant FAQ/objection handling only if needed.
8. Project Planner CTA.
9. Footer.

Logic:
**Understand → Explore → See proof → Understand the method → Act**

## 4. Services directory

Purpose:
help the user find the right solution, not display a catalog wall.

Structure:
- Directory Hero.
- 3 service families.
- 8 official services.
- short purpose for each service.
- optional related proof.
- "not sure?" planner CTA.

Each service card:
- title;
- one useful sentence;
- action.

No repeated long descriptions.

## 5. Service detail

Purpose:
reduce uncertainty before contact.

Sequence:
1. Breadcrumb.
2. Detail Hero.
3. Who it fits / problem.
4. Scope.
5. Deliverables.
6. Possible integrations/capabilities where relevant.
7. Related verified work.
8. Service-specific process.
9. FAQ.
10. Planner CTA.

Do not add price/duration/support promises until approved as real business rules.

## 6. Portfolio

Purpose:
evidence browser.

Listing card:
- category/year if verified;
- project title;
- one-sentence definition;
- action.

Filters must reflect real data.

A project is not a fake case study. Missing fields remain missing.

## 7. Case study

When enough verified information exists:

1. Evidence Hero.
2. Project identity/meta.
3. Overview.
4. Context/challenge — only if verified.
5. What Wasl built.
6. Key screens/media.
7. Verified technologies if relevant.
8. Verified delivered outcomes.
9. Live link when public.
10. Related work.
11. Similar-project CTA.

Writing logic:
**Context → Problem → Work → Evidence → Next action**

## 8. About

Purpose:
explain how Wasl Tech thinks.

Sequence:
- concise positioning;
- what Wasl combines;
- operating principles;
- what we build;
- decision philosophy;
- market;
- next action.

Avoid generic corporate history/filler.

## 9. Process

Purpose:
show how uncertainty becomes a clear project.

Each phase copy:
**phase name + what happens + what comes out of it.**

Do not invent timelines.

## 10. Contact / Project Planner

Primary model:
structured planning conversation.

Planner stages:

### Step 1 — Need
- website
- application
- store
- system/programming
- technical solution
- identity/design
- profile
- marketing
- unsure

### Step 2 — Project stage
- new idea
- existing / improve
- redesign
- add functionality
- unsure

### Step 3 — Priority
- MVP/first usable version
- full scoped version
- phased improvement
- consultation first

### Step 4 — Context
- name
- WhatsApp
- company/project
- current URL optional
- concise brief

Final behavior:
prepare/send a truthful structured lead through approved channel. No fake success state.

## 11. Writing hierarchy

### Eyebrow / kicker
Orientation only:
- الخدمات
- أعمال مختارة
- دراسة حالة
- قبل التنفيذ
- ما قمنا به
- ابدأ مشروعك

### Heading
Carries the idea.

Bad:
> خدماتنا

Better pattern:
> حلول رقمية مرتبة حول احتياج مشروعك

### Supporting copy
Adds:
- how;
- who;
- scope;
- reason;
- next-step context.

If it merely repeats the heading, remove it.

## 12. Sentence style

Preferred:
**verb + clear object + useful outcome/context**

Example pattern:
> نطوّر لوحة إدارة تنظّم المحتوى والصلاحيات وتسهّل متابعة العمل.

Avoid:
> نقدم أفضل الحلول المبتكرة بأعلى جودة واحترافية.

## 13. Service writing formula

- service name;
- value line;
- who it fits;
- what is built;
- what is delivered;
- integrations/capabilities;
- process;
- proof;
- FAQ;
- CTA.

Deliverables must be deliverables, not adjectives.

Good:
- responsive pages
- admin panel
- API integration
- content structure
- launch setup

Bad:
- creativity
- professionalism
- excellence

## 14. CTA system

Explore:
- شاهد الأعمال
- استكشف الخدمة
- اقرأ دراسة الحالة

Start:
- ابدأ مشروعك
- خطط مشروعك
- ناقش احتياجك

Continue:
- الخطوة التالية
- السابق
- راجع الطلب

Avoid:
- المزيد
- اضغط هنا

unless context makes the destination unambiguous.

## 15. Technology writing

Do not create a technology-logo wall as a substitute for value.

Technology appears:
- in a service when it changes platform/capability decisions;
- in a case study when verified;
- in engineering/process content when relevant.

Never claim a stack from inference.

## 16. Content density

Hero:
- one H1
- short support
- 1–2 actions
- optional visual/meta

Card:
- title
- 1 sentence
- action/meta

CTA:
- heading
- one support line
- 1–2 actions

FAQ:
use real objections, not marketing statements disguised as questions.

## 17. Arabic writing

- Modern clear Arabic.
- Avoid inflated formal prose.
- Keep Yemeni/Gulf audiences in mind without forcing dialect into core website copy.
- English technical terms are used only when clearer or industry-standard.
- Arabic labels stay RTL and readable.

## 18. Content integrity

Never invent:
- metrics;
- clients;
- testimonials;
- results;
- technologies;
- duration;
- prices;
- SLAs;
- team members;
- certifications.

Use:
- `NOT VERIFIED`
- `CONTENT REQUIRED`

during implementation rather than filling gaps.
