# منصة هِمّة التعليمية | Himma Learning Platform

> **مسودة تحريرية للمراجعة — غير منشورة.** الحقائق الأساسية مستمدة من وصف المشروع الحالي في المستودع، أما تفسير التحديات وقرارات التصميم فهو صياغة مقترحة تحتاج اعتماد مالك المشروع قبل نشرها. لا توجد أرقام أداء أو نتائج عملاء مثبتة هنا.

**مسار المشروع:** `/portfolio/himma-learning-platform/` — **نوعه:** app — **مرجع الصورة:** `/assets/works/himma.webp`

## النسخة العربية المقترحة

### نبذة المشروع
هِمّة منصة تعليمية عربية تتمحور حول رحلة الطالب في مهارات القراءة والكتابة، لا حول عرض دروس منفصلة فقط. تتناول دراسة الحالة كيفية الجمع بين تقدير مستوى البداية، وممارسة المهارة عبر نشاط مناسب، ثم توفير صورة أوضح عن متابعة الطالب في لوحة الإدارة. هذه العناصر واردة في وصف المشروع المعروض لدى وصل تك؛ تفاصيل النسخة التشغيلية الحالية تحتاج مطابقتها مع المشروع قبل النشر.

### المشكلة والسياق
التعليم التفاعلي لا يصبح مفيدًا بمجرد عرض أسئلة كثيرة. يجب أن يفهم الطفل المطلوب منه وأن يرتبط التدريب بمستوى المهارة، وأن تكون للإدارة طريقة منظمة لرؤية المسار بدل التعامل مع الأنشطة والبيانات كعناصر منفصلة. هنا يظهر تحدي تصميم تجربة بسيطة للطالب، وفي الوقت نفسه كافية للإدارة.

### نهج الحل ومساهمة وصل تك
يصف نطاق العمل واجهات للتقييم القبلي، ومسارًا لأنشطة القراءة والكتابة، ولوحة متابعة وإدارة للطلاب. الصياغة المقترحة تبرز الفصل بين تجربة الطفل وخدمات الإدارة، والاعتماد على تدرج التعلم. ينبغي توضيح ما هو منفذ حاليًا وما يزال ضمن النسخة التطويرية الثانية قبل وصفه بأنه متاح للعامة.

### القرارات التفسيرية المقترحة — للمراجعة
1. الفصل بين واجهة الطالب البسيطة ولوحة الإدارة ذات المعلومات الأكثر تفصيلًا.
2. ربط التقييم المبدئي بمسار المهارات بدل تقديم النشاط نفسه لكل مستخدم.
3. تنظيم التمارين والمتابعة داخل رحلة واضحة يمكن مراجعتها تربويًا.

### نطاق العمل المسجل بالفعل
- التقييم القبلي ومسار الطالب
- أنشطة القراءة والكتابة والتدريبات
- لوحة إدارة الطلاب والمتابعة

### المخرجات المسجلة
- واجهة تعلم تفاعلية للطالب
- مسار مهارات وأنشطة تعليمية
- لوحة إدارة لمتابعة الطلاب

## English editorial draft

### Project overview
Himma is an Arabic learning experience focused on reading and writing skills. The case study examines how an initial assessment, guided practice and administration tools can form a coherent learning journey rather than a set of unrelated exercises. The published portfolio lists these elements, but the exact currently released feature set needs owner confirmation.

### Challenge
Young learners need clear, manageable activities, while educators need a structured view of progression. Combining those needs without making the child-facing interface too complex is the central design question.

### Approach
The recorded scope includes an initial assessment, learning activities and a student-management interface. A useful case study should separate student and administrator journeys and clearly distinguish the implemented release from planned V2 learning features.

### Suggested design rationale — to be verified
1. Separate the child's task-focused interface from educator administration.
2. Use baseline assessment to inform a staged learning journey.
3. Organize practice and progress review around identifiable skills.

### Recorded scope
- Initial assessment and student journey
- Reading and writing learning activities
- Student management and progress tracking
