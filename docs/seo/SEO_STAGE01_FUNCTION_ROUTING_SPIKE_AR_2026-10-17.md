# تجربة هندسية معزولة — إصلاح أولوية التوجيه القديم من جذوره

**التاريخ:** 17 أكتوبر 2026. **الفرع:** `seo/stage01-function-routing-spike-20261017` مشتق من PR #67. **الحالة: بحث/تجربة كود ناجحة محليًا، لا نشر ولا دمج.**

## لماذا لم يُقبل PR #67؟

تحققت معاينة Vercel المباشرة على SHA سابق من PR #67 ووجدنا:
- `/index.html` و`/en/index.html` ما زالا 200 بدل 308.
- عدة قيم `id` للخدمات القديمة تعطي وجهة دليل الخدمات بدل تفاصيل الخدمة.
- فقدان `en` لبعض الطلبات وغياب 404 الحقيقي للمجهول.

**تفسير مرجح مدعوم بتوثيق Vercel الحالي، لا إثبات قطعياً لكل حالة:** وجود 96 Redirect شرطياً على بضعة مصادر متشابهة يجعل ترتيب تقييم `has(query)` وتفاعل البنية القديمة `routes` صعب الضمان، ووثائق Vercel تذكر قيدًا على عدد `has` المتطابقة. كما تحذر وثائق Vercel من مزج `routes` مع `redirects`/خصائص عليا؛ الأساس المنشور نفسه يحتفظ `routes` و`trailingSlash`، لذا لا ندعي حل جميع تعارضات إعداد المشروع بمجرد تغيير ترتيب القواعد.

## مسار التجربة الجديد

1. تقليل توجيه الخدمات من **96 قاعدة لها شروط متكررة** إلى **قاعدتي توجيه إلى وظيفة واحدة** قبل `handle:filesystem`، واحدة للعربية وواحدة للإنجليزية.
2. `src/seo/resolve-historical-service.js`: تحوّل `id` القديم الدقيق أو slug الرسمي من مصدر الخدمات الثماني إلى المسار الصحيح فقط؛ القيمة المجهولة لا تعود إلى دليل خدمات عام.
3. `api/legacy-service.js`: Vercel Function تستقبل `language` و`id`؛ ترجع 308 مع `Location` نسبي نظيف بلا query legacy عند التطابق، و404 بلا تحويل عند القيم المجهولة/المكررة، و405 للوسائل الأخرى. لا استدعاءات خارجية ولا بيانات سرية.
4. `vercel.json`: تجربة استخدام `routes` فقط للتوجيه القديم مع الإبقاء على 9 تحويلات HTML و404 المترجمة ورؤوس الحماية القديمة. **لا يوجد `redirects` علوي في هذه التجربة**. ما زال `trailingSlash:true` من المشروع الأساس، ويلزم تأكيد توافقه مع هذه الصيغة على Vercel.
5. `scripts/check-legacy-redirects.mjs`: اختبار جميع الخدمات وقيم IDs باللغتين، والتحقق من الوجهات مقابل `getIndexableEntries()`، والرفض الصارم للمعرفات الغريبة والمكررة، والحفاظ على HEAD/GET. لا يعتمد على 105 قاعدة سابقة.
6. `scripts/check-legacy-redirects-live.mjs`: بوابة قبول HTTP حقيقية معدة للاستخدام لاحقًا ضد Preview مطابق لـSHA، تتحقق من HTML 308، وأشكال الروابط الثلاثة لكل خدمة باللغتين، و404، وعدم تسريب `id` للوجهة، وصفحات 200 مع Canonical صحيح.

## ما يثبت وما لا يثبت

- **يثبت الاختبار البنيوي** صحة resolver ونتائج Function وتطابق المسارات المحددة مع مصادر المشروع، وعدم اعتماد حلقة طويلة من شروط `has`.
- **لا يثبت** أن Vercel سيرسل الطلب الأصلي ومعامل `id` إلى الوظيفة عند تنفيذ `routes.dest`، أو أن `index.html` سيتجاوز خاصية الملف الثابت؛ هذه بوابات لا يمكن غلقها إلا عبر Preview HTTP.
- **قرار صارم:** لا تدمج هذا الفرع في main ولا PR #67 قبل معاينة Vercel مطابقة وتشغيل المصفوفة الحية كاملة. أي فشل يعاد تشخيصه لا ترقيعه بحشو قواعد جديدة.
- لا يُغيّر هذا الفرع الـ88 صفحة، ولا الـcanonical/hreflang، ولا الـSitemap أو SEO للمحتوى؛ تعديل Vercel route فقط في فرع تجربة.

## خطوات اختبار ما بعد تجدد الحد

1. افحص حالة حصة Vercel ثم أنشئ **معاينة واحدة** للـSHA النهائي لهذه التجربة، لا Production.
2. تأكد من تجهيز Route/function `/api/legacy-service` في النشر ومن أن route rewrites ترسل المعاملات بنفس الصيغة المطلوبة.
3. شغّل `PREVIEW_BASE_URL=https://<preview>.vercel.app node scripts/check-legacy-redirects-live.mjs` من بيئة موثوقة بدون نشر أي أسرار.
4. اختبر بشكل خاص `/index.html` و`/en/index.html` و`/en/service-web.html?id=store` و`/service-web?id=web-development` وunknown ID، ثم كل المصفوفة.
5. إذا نجح، انقل التصميم المعماري **المثبت** إلى فرع PR #67، أعد CI/Preview، ثم يقرر المستخدم الدمج الرسمي.

### ما كشفته التجارب المستقلة

- مع معاينة `seo/stage01-edge-diagnostic-20261017` جرى إدراج مساري تشخيص قبل `handle:filesystem`، مع محاولات تعديل أولوية قواعد الخدمة؛ لم تتغير مخرجات الروابط التاريخية.
- وفي `seo/stage01-routing-diagnostic-v2-20261017`، أُزيل تركيب regex المعقد واستُخدمت قواعد literal لمسارات الخدمة، وأُضيفت وجهة HTML اختبارية ووظيفة اختبارية مستقلة. جرى الوصول إلى `/about/` و`/en/services/ecommerce/` من المسارات الاختبارية، **لكن الروابط التاريخية بقيت خاطئة**.
- الاستنتاج المثبت: **دالة resolver قابلة للاستدعاء، ومجرد تبسيط مسارات `routes`/تغيير ترتيبها لم يحل توجيه الروابط التاريخية**. سبب الاعتراض على هذه المسارات يحتاج تحليلًا إضافيًا لمخرجات Vercel Routing/Build Output (أو قاعدة تطبيق معاد توليدها) قبل النشر.
- أدوات جلب المعاينات قد تتبع التحويلات، لذلك **يجب الاعتماد على اختبارات first-hop GET/HEAD وLocation بدون متابعة عبر سطر أوامر بيئة CI مسموح بها** حتى لا تختلط الحالة الأولى بالصفحة النهائية.
