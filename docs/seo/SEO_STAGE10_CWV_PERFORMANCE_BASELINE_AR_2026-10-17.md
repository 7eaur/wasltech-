## مصدر بيانات Core Web Vitals

تم استدعاء `get_core_web_vitals` على موقع وصل تك لكلا `PHONE` و`DESKTOP` من اتصال GSC Wizard النشط. **النتيجة نفسها في الجهازين: `notConfigured: true`، لا يوجد مفتاح API مفعّل لخدمة Chrome UX Report (CrUX).**

لا يجوز استنتاج قيم LCP/INP/CLS أو التحسن الفعلي من ذلك. ينبغي تفعيل CrUX API Key في إعدادات GSC Wizard نفسها (خدمة Core Web Vitals) مع مراعاة الخصوصية وعدم وضع المفتاح في GitHub.

## حراس أداء موجودون بالفعل

- `scripts/check-final-media.mjs` يتحقق من 8 أزواج صور JPEG/WebP بسجل sha256، وأبعادها ونسبة مطابقتها للملفات التشغيلية، ويضع ميزانية **≤180KB** لهذه المجموعة؛ هذا حارس مجموعة صور محددة وليس حدًا شاملًا لكل الصور.
- توليد الصور والخطوط وCSS موجود في بنية `scripts/build.mjs`، ومعظم الصفحات تحتوي على responsive hero media؛ لكن هذا **لا يثبت** سرعة اتصال فعلي أو CWV.
- لا تُضبط cache lifetimes لــHTML/الأصول بناءً على `max-age=0` وحده؛ وجود `x-vercel-cache: HIT` في ردود سابقة يدل على عمل CDN لبعض المسارات ولا يثبت جودة كل مورد.

## مهمة القياس المطلوبة عند السماح بأدوات أداء فعلية

1. خط أساس PSI/CrUX Mobile/Desktop لكل نمط (home/services/detail/project/article/contact) مع وقت وتاريخ وظروف الجهاز.
2. فحص `LCP/INP/CLS` (p75 إن توفر Field data)، وتحميل الصور/fonts/JS، وفحص LCP image priority لاختلاف صفحات الجوال.
3. إصلاحات **متعلقة بقياس مثبت** في فرع مستقل، لا تكرار ضغط صور عشوائي يمكن أن يضر الوضوح.
4. مقارنة بعد الإصلاح في ظروف متماثلة، واختبار ارتفاع CLS/انزلاق التصميم/RTL/LTR.
5. Preview من SHA نفسه قبل دمج أي تغيير أداء في الموقع الرسمي.

**الحالة:** توجد اختبارات سلامة صور، لكن قياس CWV الحي ناقص بسبب مصدر CrUX غير مهيأ. لم تُنفذ إصلاحات سرعة تجميلية بلا إثبات.
