## 1) مصفوفة فحص إلزامية لكل URL

استخرج كافة الروابط من Sitemap الإنتاج وsrc/seo/indexable-routes.js، وطابقها مع GSC Indexing Tracker. قد يتغير عدد 88 لاحقًا. **سجل صفًا منفصلًا لكل URL** يتضمن:

| المحور | الأدلة والحقول المطلوبة |
|---|---|
| الهوية | URL، اللغة، نوع الصفحة، نظير AR/EN |
| الوصول | HTTP/status، سلاسل www/old redirects، 404/5xx/soft404 |
| Google indexing | Inspection verdict + coverage + تاريخ الفحص، لا تخمن من sitemap |
| توجيهات الزحف | robots.txt، X-Robots-Tag، meta robots، canonical |
| تعدد اللغات | hreflang AR/EN وx-default والتبادلية وعدم أخطاء المسار |
| إمكانية الاكتشاف | sitemap، inlinks، عمق الروابط، orphan pages، breadcrumbs |
| القصد/المنافسة | keyword intent، primary target، synonym groups، تنازع cannibalization |
| On-page | Title، Meta description، H1/H2/H3، تفرد العناوين والنص، FAQ |
| Structured data | JSON-LD الصحيح والمطابق للمحتوى المرئي والكيان |
| التجربة/الأصول | Mobile وRTL وALT والصور والحجم وCWV عند توفر قياس موثوق |
| النتائج | GSC impressions/clicks/CTR/position حسب صفحة وبلد ولغة وجهاز والفترة |
| AI search | قابلية استخراج إجابات دقيقة ودليل الخبرة والكيان والروابط الموثوقة |
| إغلاق الفجوة | P0–P3، دليل المشكلة، سببها الجذري، الحل، CI/Preview/Production وSHA |

لا تعتبر الفحص مكتملًا دون سجل يغطي **100% من روابط Sitemap**؛ البيانات غير المتاحة تُكتب "غير متحقق" ولا توصف بـPASS.

## 4) خريطة الكلمات وتحسين SEO للخدمات

لكل خدمة وثق: (1) نية تجارية واحدة أساسية؛ (2) مرادفات طبيعية AR/EN لكل سوق؛ (3) صفحة هبوط canonical؛ (4) مقالات تساندها؛ (5) مشاريع تثبت الخبرة؛ (6) بيانات GSC لهذا الاستعلام؛ (7) منافسي نتائج البحث الفعلية عند توفر أدلة حديثة للبلد والجهاز؛ (8) فجوة المحتوى والاستفادة المتوقعة دون ضمان النتيجة.

ابنِ جدول **keyword → intent → canonical page → supporting pages → current metrics → fix**، ثم افحص المنافسة داخل الموقع نفسه كي لا تنافس صفحات الخدمة والمقال والمشروع على نفس القصد. لا تعتمد على إضافة meta keywords، ولا حشو الكلمات أو شراء الروابط.

## 6) مراجعة بقية المشاريع والصفحات

افحص كل واحد من المشاريع الـ16 حسب تخصصه، وحقول data/projects.js وserviceIds:
- منصة هِمّة: تجربة تعليمية/مسار مهارات/لوحة متابعة بحسب الوظائف المثبتة.
- لوحة ميكروتيك: أتمتة إدارة المستخدمين والكروت والجلسات كما هو مطبق.
- الصور والعمل الحر والمتاجر والهوية والحملات: أدلة أصلية لكل نوع، لا فرض قالب تقني واحد على الجميع.
- إذا كانت هناك معلومات/صور/مواقع عميل مفقودة، سجل المطلوب من المستخدم بوضوح بدل ابتكارها.

افحص صفحات الخدمات والعامة/المقالات كذلك: إجابات واضحة للأسئلة، تنظيم العناوين، مراجع واقعية، روابط داخلية طبيعية، محتوى ثنائي اللغة متكافئ، تعريف الشركة/الفريق بدون ادعاءات غير مثبتة، وملاءمة سياق اليمن والخليج. التقييم لا يقتصر على الروابط الأربع أو Update Card.

## 7) AI Search / GEO / AEO

راجع إمكانية الزحف والفهرسة للمحتوى بصيغته HTML، وrobots ذات الصلة، ووضوح معلومات النشاط/العمل والخبرة وأسماء الخدمات. تحقق من Organization وWebSite وService وCreativeWork وArticle وBreadcrumbList وFAQPage وفق المحتوى الظاهر، ولا تضف schema مضللة أو FAQ غير موجودة.

ارصد **دليلًا فعليًا** للذكر/الاقتباس أو إحالات AI عبر GA4 متى أمكن، مع تمييزها عن Search Console وعن فرضية query shape. لا تساوِ "مسموح للزاحف" مع "يظهر في إجابات الذكاء الاصطناعي". العنوان/الهوية/الحسابات الرسمية لا تعني محليًا عنوانًا فعليًا أو تقييمات يجوز اختلاقها.

## 8) دورة التنفيذ وQA

1. قبل التغييرات: سجل HEAD/GSC baseline وحالة www/apex والصفحات المعنية وتاريخ البيانات المستقرة.
2. اعمل في فرع SEO مستقل لكل دفعة، وحافظ على وظائف الموقع وهيكله وبنيته AR/EN؛ لا تتداخل مع خطة النشر التسويقي.
3. شغّل Node 24 وnpm run vnext:verify وnpm run vnext:verify:release وnode scripts/check-final-media.mjs، وافحص Actions وVercel Preview وSchema/HTML والروابط.
4. عند فشل CI أو Production smoke أوقف الدمج وأصلح السبب الجذري. لا تتلاعب بالاختبارات كي تجعلها خضراء.
5. بعد الدمج تحقّق من أن Production READY لنفس SHA، ومن canonical/robots/hreflang/sitemap للصفحات المتأثرة.
6. تحديث Google قد يتأخر. لا تعتبر مجرد إعادة إرسال Sitemap طلب فهرسة لكل URL، ولا تخلط IndexNow بGoogle.
7. حدث السجل في المستودع: URL + Gap ID + P + evidence + fix + PR/SHA + test/preview + indexing/performance after + next unfinished step.
8. **كل مرحلة تُسلَّم للمستخدم للمراجعة قبل الانتقال للمرحلة التالية؛ لا تنتقل إلا بعد تأكيده.**

## 9) أول خطوة غير منجزة

**إنشاء سجل فحص شامل لكل URL منشور (88 حاليًا)**، إعادة التحقق من الأربع حالات ومن legacy redirects/Canonical، ثم معالجة أول دفعة P0/P1 **فقط بناءً على دليل**، مع الحفاظ على تقرير حالة يحدد بوضوح المكتمل/غير المكتمل. تحسين صفحات المشاريع وصفحات الخدمات بعد التخطيط والتقييم لا يزال غير منفذ في هذا التسليم.
