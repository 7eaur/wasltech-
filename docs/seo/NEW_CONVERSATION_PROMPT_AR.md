## مسؤولياتك الأساسية

أولًا: **أجرِ تدقيقًا احترافيًا مستقلًا شاملًا لكل صفحات الموقع، وليس الأربع صفحات فقط**، بالعربية والإنجليزية: الوصول والكانونيكال وتحويلات www/HTTP والروابط القديمة (.html وservice-web?id)، robots والسitemap وفهرسة Google، العناوين والأوصاف والقصد والكلمات، التكرار والتنافس الداخلي، H1/H2، ALT والوسائط والسرعة/CWV، Schema وBreadcrumb، الروابط الداخلية، FAQ/المقالات، وتجربة الهاتف. أنشئ داخل المستودع سجلًا يغطّي كل رابط فعلي مع **المشكلة والدليل والدرجة P0–P3 والحل المقترح والحالة**.

ثانيًا: عالج **المشاكل الأربع المتبقية في الفهرسة** بعد تحديد الأسباب الحقيقية. لا تفترض أن اكتشافها في Sitemap يعني فهرستها. لا تكرر إعادة طلب الفهرسة دون داع، ولا تستخدم IndexNow باعتباره أداة فهرسة Google.

ثالثًا: راجع **جميع صفحات الخدمات الثمان بلغتين**، وابنِ خريطة intent/keywords/target URLs للمنافسة على عمليات البحث عن تصميم وتطوير المواقع والتطبيقات والمتاجر والأنظمة والتسويق والهوية في اليمن والخليج، **بلا keyword stuffing أو وعود تصدر مضمونة**.

رابعًا: راجع **كل صفحات المشاريع الـ16 بالعربية والإنجليزية**، وقارن مشروع **Update Card** بالتفصيل مع المشاريع الأخرى (هِمّة، الميكروتيك، صوركم، منصة وصل، المتاجر، الهويات، التسويق...). اجعل Update Card نموذج تحسين أول: SEO title/meta، دراسة حالة أصلية عن المشكلة وطريقة التنفيذ والنتائج الوصفية المثبتة، مشروع حي إن تحقق، صور فعلية محسّنة، روابط مرتبطة بخدمة، Schema دقيقة. بعدها طبّق **المعايير لا النص نفسه** على بقية المشاريع. تجنب تلفيق شهادات ونتائج أو نسخ متشابهة.

خامسًا: اختبر قابلية ظهور وصل تك في محركات **AI Search** دون تضليل: crawl/robots، تعريف الكيان Organization، الأدلة العملية، إجابات صالحة للاقتباس، Schema، الحسابات الرسمية وروابط مصادر موثوقة؛ افصل النتائج الفعلية عن احتمالات/heuristics، ولا تعد بنشر داخل ChatGPT أو Google AI Overview.

سادسًا: راجع باقي الصفحات والمقالات وملاءمة الجمهور والدليل على الخبرة والروابط القديمة، واستخرج فجوات إضافية لا تظهر في التقرير السابق. لا تتطرق إلى استراتيجية منشورات السوشيال أو مشروع Update Card المستقل إلا بوصفه شاهدًا على المشروع.

## منهج العمل الإلزامي

- اعمل على **مراحل**؛ ابدأ الآن بفحص HEAD والمصادر المتصلة وإنشاء تدقيق شامل وسجل فجوات. ثم نفّذ أول دفعة P0/P1 ذات أولوية على **فرع SEO مستقل**. لا تعمل على main مباشرة.
- اعتمد أصل المشكلة ولا ترقيعات، واحفظ هيكلة الملفات وأسماء الدوال ومحتوى الموقع الصحيح.
- شغّل Node 24: npm run vnext:verify ؛ npm run vnext:verify:release ؛ node scripts/check-final-media.mjs؛ وتحقق من GitHub Actions/Vercel Preview وكلتا اللغتين. لا تدمج قبل نجاح الفحص. تحقّق من Production بعد الدمج عندما يتم ذلك.
- وثّق في المستودع بعد كل دفعة: البداية والنهاية SHA، الروابط المدققة/المعدلة، نتائج GSC السابقة والجديدة، ما أنجز، ما تبقى، CI/Preview والرابط والدليل، والخطوة القادمة بدقة.
- لا تتظاهر بإتاحة أداة أو بيانات مفقودة. اطلب ربط الأداة فقط إذا لم تعد موجودة.
- **لا تنتقل بين مراحل التنفيذ حتى أقول «تم»**. سلّمني أولًا تقريرًا واضحًا عن الفجوات المؤكدة وأول دفعة تحسين منجزة مع روابط التوثيق، ثم انتظر موافقتي.
