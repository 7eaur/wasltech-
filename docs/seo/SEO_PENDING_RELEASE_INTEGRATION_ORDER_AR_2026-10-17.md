## متى نعتبر النشر آمنًا؟

1. **ابدأ بالمرحلة 01**: تجربة `seo/stage01-route-validation-20261017` لم تُنشر بسبب Vercel 402 `api-deployments-free-per-day`. لا تدمجها عشوائيًا؛ يجب أن تحل الانحراف المثبت لـ`/index.html` و`/en/index.html`، والـID الطويل، والمجهول، وحفظ EN، وعدم إعادة توجيه Preview إلى مسارات خاطئة.
2. أي commit للتصحيح يحتاج `npm run vnext:verify` و`npm run vnext:verify:release` و`node scripts/check-final-media.mjs` ثم GitHub Actions وPreview **لآخر SHA نفسه**.
3. **الفروع مبنية بصورة مستقلة على `main` القديم** وليست مكدسة تلقائيًا. قبل دمج كل PR لاحق راجع Diff مع `main` الحديث، واحل تعارضات `.github/workflows/vnext-verify.yml` المحتملة بين #67/#72/#73/#75 **بحفظ جميع خطوات التحقق وعدم الكتابة فوقها**. إذا تغيّر SHA يعاد تشغيل جميع البوابات.
4. تحقق من عدم تداخل تعديلاته مع فرع التصميم البصري الجاري؛ لا تعتبر تجاوز اختبار CSS/مسارات الجوال مقبولًا.
5. بعد الدمج، انتظر Vercel Production READY على SHA الجديد وافحص HTTP وأساس SEO (canonical/hreflang/robots/sitemap/JSON-LD) قبل المرحلة التالية.
6. بعد كل مرحلة منشورة حدث ملفات التوثيق وسجل الفجوات، ثم راقب GSC/Bing/GA4 عند توفر بيانات ناضجة. لا تتعامل مع IndexNow على أنه طلب فهرسة Google، ولا ترسل روابط فرع Preview.
7. مراجعة privacy/cookie consent مطلوبة قبل #75، وملف CrUX مفتاح API إعداد حساب وليس طلب مشاركته في المحادثة.
