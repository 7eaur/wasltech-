## التشخيص قبل التنفيذ

فحص القوالب و`src/data/services.js` أظهر أن كل خدمة تحتوي أصلًا على بيانات مهنية حقيقية: وصف الخدمة، الحالات المناسبة، الجمهور، قائمة الخدمات الفرعية (بمرابط)، المخرجات، عملية العمل، القيود، FAQ، روابط مقالات ذات صلة، وأعمال مرتبطة بـ`serviceIds`. لذلك **إضافة فقرات عامة لكل خدمة أو تكرار كلمات بحث ستكون حشوًا لا إصلاحًا**.

**الفجوة العملية المثبتة:** الزائر الذي يتردد بين خدمتين متقاربتين لا يجد مقارنة حاسمة في موضع مناسب داخل صفحة الخدمة، مثل مواقع الشركات/المتاجر، الأنظمة المخصصة/الربط التقني، الهوية/بروفايل الشركات. هذا يمنع إجابة مفيدة لبعض أسئلة البحث التجارية ويمكن أن يجعل الصفحات متداخلة القصد.

## التنفيذ

- مصدر محتوى جديد `src/data/service-choices.js`: **8 قرارات خدمة مميزة × لغتين** مع سؤال صريح وجواب يوضح متى تختار خدمة أخرى ورابط لخدمتها الصحيحة. تمييز الخدمة الحالية عن بديل واحد ملائم، بلا ادعاءات أو نسب نتائج/تكلفة/شهادات.
- مكوّن `src/components/ServiceChoice.js` منفصل: HTML مقروء دون JS، سؤال `H2` ونص جواب رابط خدمة باللغة نفسها، بإعادة استخدام نظام بطاقات روابط المقالات القائم دون نظام CSS إضافي أو العبث بالتصميم.
- `src/pages/service-detail.js`: عنصر مستقل ضمن تسلسل الصفحة بعد الخدمات الفرعية؛ لا إضافة صفحة هبوط مكررة أو تغيير بنية Sitemap.
- `scripts/check-service-details.mjs`: فحص **كل الـ16** للعنوان والجواب والرابط الصحيح إلى الوجهة الموثقة، ومنع البديل الذاتي أو تكرار/غياب القسم. يتوقف build عند أي نقص.
