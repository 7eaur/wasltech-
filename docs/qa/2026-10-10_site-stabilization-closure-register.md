### نطاق كل مهمة ومعيار الإغلاق

**WT-001 — حالة موحّدة:** تدوين HEAD الحقيقي، حالة VNext المنشورة، فرع العمل النشط، المحجوز للفرق الأخرى، النواقص المحددة والمسار التالي في بداية PROJECT_STATUS.md/PROJECT_HANDOFF.md وتحديث docs/README.md. الاستعاضة عن تعليمات «لا تدمج VNext أبدًا» التاريخية بتعليمات «لا تنشر/تدمج هذا الإصدار دون موافقة» مع حفظ التاريخ. **الإغلاق:** القراءة من الملفات وحدها لا تعيد الوكيل لحالة سبتمبر القديمة.

**WT-002 — عزل العمل:** إنشاء/اعتماد فرع تجميعي للإصلاحات من أحدث main؛ الاحتفاظ بفروع SEO/أنميشن دون كتابة؛ الحفاظ على نتيجة عمل الفرعين media و404 ودمجهما بعد نجاح الاختبارات. قبل دمج كل دفعة: compare main + تعارضات مسارات / ownership. **الإغلاق:** لا تغييرات خارج النطاق أو تضارب مع الفريقين.

**WT-003/004/005 — الصور:** يجب وجود هذه الثمانية بأسمائها النهائية: services-hero.webp، portfolio-hero.webp، process-hero.webp، contact-project-planner-hero.webp، faq-insights-hero.webp، article-website-or-web-system.webp، article-ecommerce-store-prep.webp، article-content-before-design.webp. المسار assets/media/، والأصول النظيرة غير المحوّلة تحت assets/media/source/. يجب ألا تدخل ملفات .media-upload أو Base64 staging في إصدار الإنتاج أو PR. اختبر الربط عبر hero-media.js/articles.js/build.mjs، دقة source hash والأبعاد والمساحة وcrop وOG وPreview build. **الإغلاق:** 8/8 WebP + 8/8 originals موثّقة + لا staging + npm run vnext:verify وvnext:verify:release وroute assets pass، فحص بصري مقبول. صور HOME وABOUT والخدمات والمشاريع المتوفرة أصلًا ليست ضمن الرفع الجديد.

**WT-006 — CTA:** مطابقة نص كل رابط بوجهته في home hero (AR/EN) ومراجعة روابط CTA في Header/Footer وService/Contact/Planner والصفحات الثانوية. النص يجب أن يعد بالفعل الذي سيحدث، من غير روابط ميتة أو rel غير مناسب. **الإغلاق:** اختبارات رابط/نص + click smoke من المتصفح لكلا اللغتين.

**WT-007 — 404:** الاستفادة من فرع design/standalone-404-20261010 دون إعادة بنائه: وسط الصفحة رسم واحد خفيف، رسالة واحدة، زر واحد للرئيسية المناسبة، بلا Hero متعدد أقسام أو header/footer. احترام noindex وskip-to-content، وتحقيق HTTP 404 فعلي عند زيارة عنوان غير موجود (لا تكتفِ بوجود ملف 404.html)، والتحقق من الاستجابة العربية والإنجليزية وviewport 360/390/1440. **الإغلاق:** Build + route status + Screenshot QA + لا اختلاف لغة أو عناصر زائدة.

**WT-008/009 — UX ومسارات/بصريات:** فحص 8 خدمات وتفاصيلها، portfolio/project detail، الرئيسية، About، Process، Contact، Planner، FAQ، Insights/articles، Careers، Privacy، Terms، 404 بالعربية والإنجليزية. مصفوفة 360/390/768/1024/1366/1440 بحسب docs/core/QA_RELEASE.md. انتبه لبطاقتين في صف الجوال حيث اعتمدتا، Footer مضغوط، خط بلا تكدس، صور غير مقطوعة، حركة الروابط والتبويبات، menu/ESC/focus واللصق والنموذج، العناوين والمسافات. **الإغلاق:** كل defect مثبت بصورة Before/After أو اختبار؛ لا نصلح شيئًا لم تثبت مشكلته ولا نعيد التصميم المعتمد لمجرد التجميل.

**WT-010/011/012 — الأداء:** فرّق بين loader الوظيفي و**أنميشن الشعار المحجوز لفريق آخر**: نفحص فقط عدم ظهور صفحة فارغة/تأخير غير مبرر، ونُبقي المحتوى متاحًا عند ضعف الشبكة أو تعطيل JS، مع اختبار Save-Data/reduced-motion، FOUT/CLS وحجم الملفات، وعدم فرض انتظار لا ينتهي. **الإغلاق:** أدلة cold-load وthrottled tests + بيانات LCP≤2.5s وINP<200ms وCLS<0.1 حيث يمكن قياسها، مع وسم أي معيار لم يُقَس بأنه غير مثبت، وليس PASS.

**WT-013/014/015 — بناء ونظافة:** لا نخلط خطأ ENOENT بفشل rate-limit. إصلاح dependency warnings، تثبيت Node 24.x إذا ثبت ملاءمته، إطلاق CI على commit مطابق، وعزل/تصنيف الفروع القديمة. حذف فرع تاريخي لا يتم إلا بعد مقارنة والتأكد من مالكه وموافقة المستخدم. **الإغلاق:** SHA build ثابت وإشارة CI صريحة وقائمة فروع صالحة للبقاء أو الإغلاق.

**WT-016/017/018 — إنتاج ودومين:** أولًا تحقق من الإعدادات الفعلية داخل الحساب الصحيح، DNS وحالة SSL وأين يصل www/root، ثم قرار توجيه واضح (www هو المرجع المذكور حاليًا في القالب). بعد إذن النشر: build واحد مجمّع، readiness READY وSHA ومراجعة HTTP 200/301/404 والروابط القديمة، وتحليل خطأ Vercel/Hobby build quota. لا تسوِّ حالة SEO والفهرسة؛ تُحَال إلى المسؤول عنها. **الإغلاق:** الدومين العام يعرض النسخة الموافَق عليها، رؤوس وتوجيهات صحيحة، تنقل الصفحة والتحويل، وسجل نشر موثق.

**WT-019/020 — القبول النهائي:** أي بند بقي OPEN أو BLOCKED يمنع إغلاق خطة الاستقرار كلها. اجمع في QA report النهائي: قائمة المسارات، Desktop/Mobile screenshots، logs، AX/keyboard/JS/network/failed assets، مقارنة source→Production، وقائمة تغيير شكل الموقع دون تجاوز النطاق. تحديث ملفات الحالة بعد أدلة حقيقية فقط.
